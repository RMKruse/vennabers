# 07 — v0.6: v0.6 lokal abnehmen und neue Benchmarkfälle dokumentieren

**What to build:** Den kumulativen v0.6-Paketkandidaten mit reversiblen Namen, vier eingefrorenen Wegen und vollständigen Referenzaufteilungen prüfen und die Nachweise lokal festhalten. Fachliche Tests und Beispiele entstehen bereits in den Funktionstickets. Die Abnahme verwendet vorhandene Paket-/Benchmarkwerkzeuge und wahrt die dokumentierte Deaktivierung von GitHub Actions.

**Blocked by:** [05 — Trainingsschema eingefrorener Workflows erhalten und dekodieren](05-schema-eingefrorene-workflows.md); [06 — Geordnete Holdouts und vollständige Referenzpartitionen nutzen](06-referenzaufteilungen.md)

**Status:** implemented locally — platform and controlled Linux release evidence remain open

- [x] Ein eindeutiger gebauter v0.6-Kandidat samt Hash und Quellstand ist Grundlage aller ausgeführten Prüfungen; Installation, Tests und Beispiele verwenden dieses Artefakt. Die Evidenzübersicht deckt acht trainierbare kodierte Verfahren, vier eingefrorene Verfahren mit/ohne Trainingsschema, vollständiges gelerntes Postprocessing, native/dekodierte Ausgaben, Referenzaufteilungen, Fehlerfälle und bisherige Fähigkeiten ab. Neue Artefakte benötigen passende neue Nachweise.
- [x] GitHub Actions bleibt entsprechend der dokumentierten Nutzerentscheidung deaktiviert. Kein Upload, Issue-/Milestone-Anlegen, Push, Remote-Trigger oder automatisches Reaktivieren gehört zum Ticket. Paketprüfungen und Berichte laufen lokal beziehungsweise auf bereits autorisierten erreichbaren Prüfmaschinen. Fehlende Plattformkapazität wird als fehlende Evidenz dokumentiert, nicht als bestandener Lauf; eine spätere Reaktivierung wäre eine separate ausdrückliche Entscheidung.
- [x] Die fachliche Roadmap-Matrix bleibt dokumentiert: aktuelle/vorherige R-Minorreihe auf Linux x86_64, Windows x86_64 und macOS Intel/ARM; zusätzlich Linux-Kern ohne Integrationspakete und vorheriges R mit deklarierten direkten Mindestversionen samt dokumentiertem transitivem Satz. R-devel/Linux ist zusätzliche Frühwarnprüfung. Ausgeführte Läufe prüfen gebautes Package, R CMD check --as-cran, Tests und installierte Beispiele. Fehler/Warnungen, begründete NOTEs, genaue Einschränkungen, Paket-/Runner-/OS-Stände und tatsächlich noch offene Gates werden einzeln ausgewiesen.
- [x] Neue Eingänge und Schemafunktionen erhalten Hilfe, installierte End-to-end-Beispiele und NEWS/Migrationshinweise; R-Untergrenze folgt weiterhin der zum Release vorherigen Minorreihe. Direkte/minimale Integrationspakete werden tatsächlich validiert, reine Kernnutzung bleibt ohne tidymodels möglich. Tests benötigen nach Umgebungsaufbau weder Python noch Netzwerk. Frische Prozesse/Worker erhalten Schemata, Modelle, Klassen-/Ereignisidentitäten und sämtliche vorhandenen Diagnosen; kein verstecktes Lernen.
- [x] Neue Benchmarkfälle verwenden 2.000 Zeilen, 500 neue Beobachtungen und zehn numerische Prädiktoren. Für eingefrorene binäre/OvO-/OvR-/IVAR-Verfahren findet ursprüngliches Workflowtraining auf separatem Bestand vor dem Messfenster statt; alle 2.000 Zeilen dienen der neuen Kalibrierung. Kodierte und unkodierte zulässige Wege sowie gemischte und geordnete Holdouts werden auf vergleichbaren Daten gemessen. Schemaerstellung, Kodierung und Dekodierung werden gesondert ausgewiesen; Eingaben/Pläne/Optionen/Seeds und Generatorstand bleiben gespeichert.
- [ ] Kumulative bisherige Fälle bleiben erhalten. Vergleichbare Fähigkeiten werden gegen einen unveränderlichen v0.5-Vorgängerstand auf derselben dokumentierten Linux-x86_64-Maschine unter gleichem kompatiblem R-/Paket-/Threadsatz erneut gemessen. Die v0.5-Evidenz bezieht sich auf ihr tatsächlich geprüftes Artefakt; spätere Commits sind nicht automatisch mitgeprüft. Neue Funktionen erhalten Ausgangsmessungen. Inkompatible Bedingungen und Verschlechterungen werden dokumentiert beziehungsweise vor Freigabe untersucht und begründet.
- [x] Messung erfolgt seriell mit einem Aufwärm- und drei Messläufen je Fall/Release, frischen R-Prozessen je Release und kontrollierbaren Pools mit einem Thread. Fit/Kalibrierung und Predict sind getrennt, vollständige äußere Bewertung gegebenenfalls zusätzlich insgesamt. Produktvalidierung bleibt im Messfenster, Datenaufbau/Installation und ursprüngliches eingefrorenes Training außerhalb. Einzelwerte, Median, Prozess-Spitzenspeicher, Modell-RDS-Größe mit identischen Speicheroptionen und frische Wiederherstellung/Vorhersagegleichheit werden protokolliert. Große Benchmarks bleiben außerhalb der CRAN-Paketprüfung.
- [x] Der lokale Abschlussbericht trennt tatsächlich bestandene Prüfungen, Grenzen und offene Freigabenachweise; eine reine lokale Probe wird nicht als vollständige Plattformfreigabe bezeichnet. Bestätigte Nutzerabweichungen von Freigaberegeln werden releasebezogen festgehalten. V0.7-Paar-/Vollmodellwege, v0.8-Tuning und v0.9-neu gelerntes Postprocessing bleiben außerhalb dieses Releases; funktionsfähiges bereits gelerntes Postprocessing im eingefrorenen Zugang gehört ausdrücklich dazu. Kein Tagging, Publishing oder CRAN-Einreichen.
